# 修复演示与证据

[delivery-report.json](delivery-report.json) 来自一次确定性离线回放：重复取消订单导致库存重复回补，首次回归测试退出码 1，修改 `inventory.py` 后再次验证退出码 0。Git diff、命令日志与运行状态均来自实际执行；模型动作由脚本指定，因此它只验证交付链路，不代表 Agent 能力。

## 60–90 秒演示顺序

1. 展示问题与失败测试：重复取消同一订单，库存只能回补一次。
2. 展示 Agent 定位函数、读取相关测试并产生最小修改。
3. 展示实际测试结果；验证失败时继续修复，达到预算则结束并说明原因。
4. 展开交付报告中的真实 diff、执行记录和退出码，复制摘要或下载 JSON。
5. 切到另一会话再返回，确认报告仍属于原会话；刷新后也能恢复。

求职演示应录制真实模型完成的任务，并在画面注明模型、仓库版本和是否人工介入。上面的离线记录可用于检查界面与报告格式，不应剪辑成真实模型成功案例。

软件行为测试、离线评分链路与真实模型任务完成率分别记录。模型对照实验见 [evals](../../evals/README.md)，原始结果与失败案例保留在对应结果目录中。
